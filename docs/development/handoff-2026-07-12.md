### アーキテクチャ（依存方向は下→上のみ）

```
pw-domain        純粋ロジック: ConversationState / SpeechSegmenter / TranscriptFilter
                 / ReplyParser(制御JSON) / SentenceSplitter / TurnTracker / strip_emoji
pw-application   ports + ユースケース: SpeechPipeline / ConversationOrchestrator(状態遷移の唯一の所有者)
adapters         pw-audio(cpal/rtrb/rubato) / pw-stt-sherpa(公式sherpa-onnx crate) / pw-llm(reqwest+SSE)
Tauri层          apps/desktop/src-tauri: 配線のみ（speech/chat/characterサービス、commands、events）
frontend         apps/desktop(React19/Vite8) + packages/live2d-runtime(React非依存controller) + packages/contracts(ts-rs生成)
```

- coreの同期実装をTDDし、スレッド化はTauri層のworker（mpsc queue）で行うパターンで統一。
- 全IPC契約は `crates/pw-contracts` のDTO（schema_version付き）→ `cargo run -p pw-contracts --bin export-bindings` でTS生成（手編集禁止）。
- Capabilityはウィンドウ別最小権限。拒否テスト（`apps/desktop/src-tauri/tests/capabilities.rs`）で固定。

### 実行系の約束事（ハマりどころ、詳細は作業内容.md）

1. **pnpmは必ず `corepack pnpm ...`**（packageManager: pnpm@11.11.0）。
2. **Tauriイベント**: 複数ウィンドウ向けは `app.emit()` **1回だけ**。単一ウィンドウ向けは `emit_to(EventTarget::webview_window(label))`。同名イベントの複数回emitは厳禁（`Any`リスナーに重複到達）。フロントは `src/shared/ipc/event-bus.ts` の `subscribeEvent` のみ使用（listen()直接使用禁止）。
3. **AI支援環境の制約**: AIのシェルはMSIXコンテナで `%APPDATA%` 書き込みが仮想化される。モデル配置スクリプトや `tauri dev` はユーザー自身のシェルで実行すること。
4. cpal 0.18は windows-core 0.61/0.62 不整合が起きる → lockで0.61.2に統一済み（`cargo update`時に注意）。rubatoは0.16固定（4.0はAPI刷新）。
5. live2d-runtimeはvendored Frameworkの制約でstrict緩和+**distビルド配布**（desktopはdist参照。`corepack pnpm build` を先に実行）。Cubismアダプタは `/cubism` サブパスをCore検出後に動的import。
6. ローカル**8080は別のpythonサービスが常駐**。LLM既定値と衝突するため、LM Studioは1234で使用し設定画面で保存する（「LLMに接続できません」の定番原因は保存忘れ）。
7. tauri devは同時1インスタンスのみ。ビルドが「アクセス拒否」で失敗したら実行中のexeを終了。

### 環境（ユーザー実機）

- モデル配置済み: `%APPDATA%/com.parallelworld.desktop/` に characters(epsilon_free) / models(silero-vad-v5, reazonspeech-k2-v2)。
- 配置スクリプト: `node tools/scripts/sync-live2d-dev-assets.mjs` / `node tools/scripts/download-stt-models.mjs`（SHA-256検証付き、キャッシュ `.models-dev/`）。
- LLM: LM Studio `http://127.0.0.1:1234/v1`（gemma系）。設定は `config/llm.json`。
- 起動: `corepack pnpm --filter @parallel-world/desktop tauri dev`

## 2. これからの実装（Phase 4〜7）

各Phase着手時に `docs/superpowers/plans/` へTDD実装計画を作成する運用（過去計画が様式の参考になる）。

### Phase 4: TTSとリップシンク（次のフェーズ）

基本設計8章・設計spec 7章参照。実装項目:

- **pw-tts crate（新規）**: AivisSpeech HTTP API adapter（loopbackのみ）。話者/スタイルは `/speakers` から動的取得（固定ID依存禁止）。ユーザー辞書。
- **TTSキュー**（pw-application）: orchestratorの `on_sentence` を文章単位で先行合成（文1再生中に文2を合成）。WAVキャッシュは app data `cache/`。
- **再生**: WebView側でWeb Audio再生（生PCMはRustのみ、WebViewへは音声ファイル識別子を渡す — asset protocolのscope追加が必要）。
- **Live2Dリップシンク**: live2d-runtimeに口パラメータ駆動を追加（再生音声のRMS→PARAM_MOUTH_OPEN_Y。epsilonのLipSyncグループはmanifest取得済み）。
- **発話割り込み**: 停止時に音声ノード・TTSキュー・口パラメータを同時停止（設計spec）。`SpeechService::set_capture_enabled(false)` をTTS再生中に呼ぶ接続（エコー防止、Phase 2で実装済みのAPI）。
- 完了条件: 文章単位の順次読み上げ / 音声・口・字幕の整合 / 割り込みで即停止。
- 注意: AivisSpeechはユーザーが別途起動する構成（初期開発）。strip_emoji済みテキストをTTSへ渡す。読み上げ正規化（数字・記号）はここで拡張。

### Phase 5: 記憶（SQLite）

- pw-storage crate: rusqlite + migration（`crates/pw-storage/migrations/` 骨格あり）。外部キー有効化・busy timeout・WAL注意（設計spec 7章）。
- 会話履歴永続化（現在はorchestrator内のcapped dequeのみ）、要約、長期記憶検索、プロンプトへの記憶注入（PromptBuilderに挿入位置のコメントあり）、削除・エクスポートUI（Settings「データ」欄）。

### Phase 6: 障害処理と長時間安定性

- 外部プロセス監視（AivisSpeech/llama-server、上限付き指数バックオフ再起動）、音声デバイス切断復旧、STT再初期化、機能別縮退の総点検、クラッシュ診断（秘密情報除去）。
- **2時間連続試験**（Phase 2から持ち越し: メモリ・キュー・タスク非増加）。診断カウンタは実装済み。

### Phase 7: 配布

- Windows installer / macOS bundle、署名付き自動更新、モデルDL+SHA-256検証の製品内蔵化（manifest形式は `content/model-manifests/` で確立済み）、ライセンス画面（文言候補: `project-input/live2d/SOURCE_URLS.md` 末尾）、CI拡張。
- **外部ゲート（コードだけでは完了不可）**: 署名証明書、Apple資格情報、updater公開URL/鍵、Live2Dリリース許諾、同梱モデル再配布許諾。許諾未確認モデルは配布物へ含めない。
