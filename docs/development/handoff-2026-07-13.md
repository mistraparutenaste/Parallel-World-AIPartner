### Phase 4のアーキテクチャ（計画: docs/superpowers/plans/2026-07-13-phase-4-tts-lipsync.md）

```
pw-tts           AivisSpeechClient(VOICEVOX互換: /speakers, /audio_query→/synthesis, user_dict CRUD)
                 WavCache(FNV-1aキー, 200件・古い順剪定) / CachedSpeechSynthesizer(TtsSynthesizer port実装)
pw-application   speech_synthesis: TtsSynthesizer / SpeechAudioSink ports
                 SpeechSynthesisQueue(直列合成, turn失効, seq採番, 失敗はturnにつき1回通知→残りスキップ)
Tauri层          TtsService(mpsc単一worker, 設定fingerprintで再構築)
                 停止 = AtomicU64失効watermark(呼び出しスレッドで即時) + speech-stop即emit
                 ChatService.on_sentence → enqueue（文N再生中に文N+1を合成 = 先読み）
frontend         SpeechAudioPlayer(AudioSink抽象, 新turn割り込み/旧turn破棄, onLevel/onActiveChange)
                 WebAudioSink(fetch→decode→RMS平滑化) → Live2DController.setLipSyncValue
                 → CubismLipSyncUpdater（モデルにLipSync群が無ければ ParamMouthOpenY フォールバック）
```

- イベント: `speech-audio` / `speech-stop` はcharacterウィンドウ単一宛（`EventTarget::webview_window`）、`tts-state`（縮退通知）は `app.emit()` 1回。
- WAVはファイルパスのみをWebViewへ渡し `convertFileSrc` で取得（asset scope `$APPDATA/cache/tts/**` 追加済み）。
- 再生中は `set_speech_playback`（character capabilityのみ）→ `SpeechService::set_capture_enabled(false)` でSTTミュート（エコー防止、Phase 2完了条件の残項目を解消）。
- TTS設定は `config/tts.json`（enabled / base_url / style_id / volume / speed）。**保存を忘れると反映されない**（LLM設定と同じUI規約）。
- エンジン障害時は `tts-state` → チャットに「音声合成に接続できません」を表示しつつテキスト会話は継続（TTS障害→テキスト表示の縮退）。

### 実行系の約束事（Phase 0〜3からの引き継ぎ + Phase 4追加）

1. **pnpmは必ず `corepack pnpm ...`**（packageManager: pnpm@11.11.0）。
2. **Tauriイベント**: 複数ウィンドウ向けは `app.emit()` **1回だけ**、単一ウィンドウ向けは `emit_to(EventTarget::webview_window(label))`。フロントは `subscribeEvent`（event-bus）のみ。
3. **AI支援環境の制約**: AIのシェルはMSIXコンテナで `%APPDATA%` 書き込みが仮想化される。モデル配置・`tauri dev`・GUIアプリ起動はユーザー自身のシェルで実行。
4. cpal 0.18のwindows-coreはlockで0.61.2固定 / rubato 0.16固定 / live2d-runtimeはdistビルド配布（`corepack pnpm build` を先に）。
5. ローカル**8080は別のpythonサービスが常駐**。LLMはLM Studio 1234を設定画面で保存して使用。
6. **ts-rsのu64はTSで`bigint`になるがJSONペイロードの実行時型はnumber** → イベントDTOの数値IDは `#[ts(type = "number")]` を付ける（turn_idで既に踏んだ。typecheck失敗の真因になる）。
7. **日本語コメント入り .ps1 はUTF-8 BOM付きで保存**（PowerShell 5.1はBOM無しUTF-8をANSI解釈しパースエラー）。
8. **endpoint検証（loopback限定）は `pw_platform::net::validate_base_url` が共通実装**（pw-llmは再エクスポート）。新しいローカルサーバーadapterでもこれを使う。
9. tauri devは同時1インスタンスのみ。「アクセス拒否」ビルド失敗は実行中exeを終了。

# Phase 6 Task 2 review rework (2026-07-13)

- `try_wait` errors are no longer treated as a running child; they emit degraded runtime health and stop/reap the owned process.
- Runtime health is emitted through an injected sink backed by `AppHandle::emit`.
- Process ownership is a typed DTO (`managed`, `external`, `not_applicable`), with an explicit `circuit_open` field.
- Existing external processes remain continuously HTTP-probed; three consecutive failures emit degraded health.
- Shutdown is terminal. Lifecycle and rearm decisions are serialized, and rearm is accepted only for a configured feature whose circuit is open.
- Rearm IPC is exposed only by the Settings capability and shown only for managed, circuit-open processes.
