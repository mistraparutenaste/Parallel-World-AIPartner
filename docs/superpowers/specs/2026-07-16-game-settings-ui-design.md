# ゲーム調設定画面デザイン

## 目的

管理画面の左カラムによる「会話・設定・ログ」の選択構造と既存機能を維持しながら、設定画面を操作しやすいゲームメニュー調のUIへ刷新する。キャラクターWindow、キャラクター描画、独立表示中のチャットWindowは変更しない。

採用案は[比較モックアップ](assets/2026-07-16-game-settings-ui-options.png)のAとする。参考画像からは、細い幾何学線、菱形のアクセント、広い余白、明確な選択状態だけを取り入れる。ハードシャドウ、過度な発光、背景ぼかし、ゲーム画面そのものの模倣は行わない。

## 対象範囲

- `SettingsWindow` が描画する管理画面シェル
- 管理画面内の左カラム、ヘッダー、テーマ選択、カテゴリタブ
- 管理画面内にドッキングされた会話、設定パネル、会話ログ、技術ログ
- 管理画面内のボタン、入力、選択、スライダー、トグル、状態表示
- ライト、ダーク、システム追従の3テーマ
- 既存のキーボード操作、ARIA属性、レスポンシブ表示

対象外は、キャラクターWindowとその透過CSS、キャラクター描画処理、Tauri Window定義、独立チャットWindowの外観、設定値やIPCの仕様変更である。

## ビジュアル方針

ライトテーマを基準とし、白に近い背景、淡い青灰色の補助面、チャコールの文字、シアンのアクセントを使う。ダークテーマは構造を変えず、濃紺の背景、青灰色の面、明るい文字、シアンのアクセントへ置き換える。

主要な造形は次のとおり。

- 角丸は小さくし、カードの丸さではなく細線と面差でグルーピングする
- 菱形はブランドマーク、選択マーカー、保存など主要操作の小さな装飾に限定する
- 選択状態はアクセント色、左辺または下辺の線、菱形マーカーの複数手掛かりで示す
- 影は原則使用せず、必要な浮遊要素にもごく弱い標準シャドウだけを許可する
- 装飾線は操作領域を横切らず、入力欄や文字の可読性を優先する
- 通常文字は4.5:1以上、境界とフォーカス表示は3:1以上を目標にする

## レイアウト

左カラムの幅と3項目の構造は維持する。各項目は高さ44px以上のクリック領域を持ち、選択項目だけにシアンの縦線と菱形マーカーを表示する。狭幅時は既存どおりアイコン中心のコンパクト表示へ切り替える。

上部ヘッダーはタイトルとテーマ選択を一列に保つ。設定カテゴリは横並びのタブとして維持し、選択カテゴリを下線と小さな菱形で示す。本文は最大幅を制限した縦スタックとし、設定セクションを細線付きのフレームで区切る。

フォームはラベルと入力の対応を揃え、可能な箇所では説明・現在値・状態を同じ行に配置する。既存の保存、接続確認、テスト再生、再試行などの操作と非同期状態は変更しない。

## コンポーネントとCSS境界

新しい視覚ルールは `.control-center` 以下を基点にスコープする。共有要素へ必要なトークンを追加しても、キャラクターWindow用の `html.transparent`、`body.transparent`、`.character-canvas` とその子孫には適用しない。

`SettingsWindow` の状態管理、IPC、タブ移動ロジックは保持する。必要なマークアップ変更は、装飾用の非表示要素またはクラス名の追加に限定する。新しい依存パッケージや画像アセットは追加せず、幾何学表現はCSSで実装する。

## 操作性とアクセシビリティ

- 左カラムとカテゴリタブは既存のWAI-ARIA Tabsパターンを維持する
- 矢印、Home、End、Tab、Enter、Spaceで既存操作が継続する
- フォーカスリングは背景テーマにかかわらず明確に表示する
- 色だけで選択、成功、警告、無効状態を伝えない
- 100%、125%、150%の表示倍率と640px以下の狭幅表示で主要操作を隠さない
- `prefers-reduced-motion` では装飾的なトランジションを停止する

## エラーと状態表示

既存のエラー処理とロールバック挙動は変更しない。エラー、成功、処理中、無効状態は共通の状態色とアイコン・文言で表現し、ゲーム調装飾より優先して読めるようにする。技術ログは現在の等幅フォントと高コントラスト表示を維持する。

## テストと検証

- 左カラムの選択と矢印キー操作の既存テストを維持する
- ゲームUI用クラスと装飾要素が管理画面に存在することを最小限のDOMテストで固定する
- キャラクターWindowのDOMと透過スタイル対象を変更していないことを差分で確認する
- frontend test、typecheck、buildを実行する
- ライトとダーク、通常幅と狭幅を実画面で撮影する
- 採用モックアップAと実装スクリーンショットを比較し、レイアウト、階層、色、幾何表現、タイポグラフィ、操作状態を確認する

## 完了条件

- 左カラムの選択構造と既存機能が維持されている
- 設定画面がA案の明るい幾何学的ゲームメニューとして統一されている
- ダークテーマも同じ構造と操作性を持つ
- キャラクターWindowと独立チャットWindowに視覚・機能差分がない
- 関連テスト、型検査、ビルド、実画面確認が成功する
