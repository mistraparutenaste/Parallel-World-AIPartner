# キャラクター別性格スライダーとダークトライアド設計

**日付:** 2026-07-16  
**実装状態:** v3へ移行済み。サディズムとユーザー共通セーフワードを含む現行仕様は追補を優先する。
**対象:** ペルソナ契約、設定永続化、プロンプト構築、Tauriコマンド、設定UI、テスト

> **追補:** サディズムを加える追加設計は
> [キャラクター別サディズム追加設計](2026-07-16-personality-sadism-extension-design.md)
> を優先する。本書は既存のv2・ダークトライアド実装の基準設計として残す。

## 1. 目的

既存のキャラクター別ペルソナに、現在の6つの会話傾向と同じ `0..=100` のダークトライアド指標を追加する。設定画面では9指標を編集でき、保存後の次のユーザーメッセージから会話へ反映する。

追加する指標は次の3つとする。

- マキャベリズム (`machiavellianism`)
- ナルシシズム (`narcissism`)
- サイコパシー (`psychopathy`)

3指標は心理診断ではなく、架空キャラクターの会話表現を調整するパラメーターである。既定値は50とする。

## 2. スコープ

### 対象

- `PersonaProfileDto` と生成済みTypeScript契約
- `personas.json` のv1からv2への後方互換移行
- キャラクター単位のペルソナ取得・保存コマンド
- 設定ウィンドウ内の性格パネル
- ダーク表現の明示的なオプトインと確認記録
- ペルソナプロンプトへの値とアプリ独自制約の反映
- 契約、移行、永続化、権限、プロンプト、React UIのテスト

### 対象外

- 人間の性格診断またはスコア算出
- LLM提供元の安全機構の解除
- Parallel Worldの上位システム指示、違法行為、自傷他害などに関する基本保護の解除
- 進行中の応答への設定差し替え
- ダークトライアド値を長期記憶から自動推定する処理

## 3. データ契約

`PersonaProfileDto` に次を追加する。

```text
machiavellianism: u8
narcissism: u8
psychopathy: u8
allow_intense_dark_expression: bool
dark_expression_acknowledgement_version: Option<u16>
```

9つのスライダー値はすべて `0..=100` で検証する。新規プロフィールでは全スライダーを50、`allow_intense_dark_expression` を `false`、同意バージョンを `None` とする。

強いダーク表現をONで保存するには、同意バージョンがアプリの現在値と一致しなければならない。OFFでは同意バージョンの有無を要求しない。警告内容を実質的に変更した場合は定数のバージョンを上げ、再同意を要求できるようにする。

## 4. 移行と永続化

`PERSONA_SETTINGS_SCHEMA_VERSION` を2へ上げる。v1を読む専用の互換経路を設け、既存フィールドをそのまま保持しながら次を補完する。

- 新しい3指標: 50
- 強いダーク表現: OFF
- 同意バージョン: なし

移行した値はメモリ上でv2として扱い、次回の明示的な保存でv2ファイルへ原子的に置換する。読込みだけで元ファイルを書き換えない。

破損JSON、重複ID、キーと `character_id` の不一致、範囲外値、未対応スキーマは保存可能な既定値へ黙って変換しない。取得コマンドは明示的なエラーを返し、既存ファイルを上書きしない。保存では全体を検証してから一時ファイルと原子的置換を使う。

## 5. コマンドと権限境界

設定UI向けにキャラクターID指定の取得・保存コマンドを公開する。コマンド名は実装計画で既存命名規則に合わせて確定する。

取得処理はインストール済みキャラクターの安定IDでプロフィールを解決する。未作成の場合は既存のレガシーキャラクタープロンプト移行を利用し、新しい既定値を持つプロフィールを返す。

保存処理は次の順で行う。

1. スキーマ、ID一致、9値の範囲を検証する。
2. 強いダーク表現がONなら現在の同意バージョンを検証する。
3. 対象キャラクターだけを更新した新しい設定スナップショットを組み立てる。
4. ファイル全体を原子的に置換する。
5. 成功したスナップショットを返す。

書込みコマンドは設定ウィンドウのcapabilityだけへ追加する。キャラクター表示ウィンドウとチャットウィンドウには書込み権限を与えない。

## 6. 設定UI

コントロールセンターの「設定 > キャラクター」内に性格パネルを追加する。インストール済みキャラクターから編集対象を選び、キャラクターごとのプロフィールを読み込む。

### 会話の傾向

既存の6項目を2列のスライダーとして表示する。

- 積極性
- 親密度
- ユーモア
- 応答の長さ
- 感情表現
- 反応間隔

### ダークトライアド

3項目を別カードへまとめる。

- マキャベリズム
- ナルシシズム
- サイコパシー

各スライダーは0と100の端点、現在の整数値、関連付けられたラベルを表示し、キーボードでも操作できる。保存ボタンと既定値へ戻すボタンを設ける。既定値への復帰は画面上のドラフトだけを変更し、保存するまで永続化しない。

ダークトライアド欄には次の警告を赤字で常時表示する。

> この性格値を高くすると、攻撃的・操作的・共感性の低い応答が増え、あなたを傷つけたり、トラウマを想起させたりする可能性があります。

その下に「強いダーク表現を許可」トグルを配置する。OFFからONにする場合だけ確認ダイアログを開く。「リスクを理解し、自己責任で有効にする」チェックが入るまで確定ボタンを無効にする。OFFへ戻す操作には確認を要求しない。

確認ダイアログには次を表示する。

> この設定は心理的負担の強い表現を増やす可能性があります。LLM提供元およびParallel Worldの基本的な安全保護は解除されません。

免責・利用上の注意として次を表示する。

> 本機能は、娯楽上のキャラクター表現を調整するものであり、心理診断、治療または医療上の助言を目的とするものではありません。生成内容は予測できず、不快感や精神的負担を生じる場合があります。内容を鵜呑みにせず、利用の継続はご自身で判断してください。強い苦痛を感じた場合は、直ちに本設定を無効化し、利用を中止してください。本表示は、法令上認められない責任まで免除するものではありません。

保存中は重複送信を防ぐ。保存失敗時は既存の永続データを変更せず、画面上のドラフトを維持して再試行できるようにする。キャラクター切替時に未保存変更がある場合は、破棄確認を表示して意図しない消失を防ぐ。

## 7. プロンプトへの反映

既存のバージョン付きペルソナJSON境界に新しいフィールドを含める。フィールド値はデータであり、上位指示を上書きできないという既存の境界を維持する。

OFFでは、ダークトライアド値を皮肉、自己中心性、冷淡さ、駆け引きなどの会話演出へ限定するアプリ指示を加える。ユーザーの弱点や保存済みのトラウマを意図的に利用する指示、脅迫、服従の強要、自傷他害の促進には変換しない。

ONでは、より強い敵対的、操作的、低共感な表現を許可する。ただし、LLM提供元の制約、上位システム指示、Parallel Worldの基本保護、保存済み機微情報を狙って攻撃しない境界は維持する。

会話処理は各ユーザーメッセージの開始時にペルソナを解決する。保存済み設定は保存成功後の次のユーザーメッセージから反映し、進行中の応答スナップショットは変更しない。

## 8. エラー処理

- 読込失敗: 編集可能な既定値へ黙って切り替えず、エラーと再読込操作を表示する。
- 保存検証失敗: 問題のある項目を示し、ドラフトを保持する。
- 原子的置換失敗: 旧ファイルを維持し、再試行可能なエラーを返す。
- キャラクター消失: 保存前に対象IDの存在を再確認し、別IDへ誤保存しない。
- 同意不一致: ON保存を拒否し、現在の警告文で再確認させる。

## 9. テスト戦略

### Rust契約・永続化

- 新規プロフィールの9値が50、強い表現がOFFである。
- 9値の0と100を受理し、101を拒否する。
- ONかつ同意なし・旧バージョンを拒否する。
- v1からv2へ既存データを失わず補完できる。
- v2の保存と再読込が一致する。
- 破損データ、未知スキーマ、ID不一致を上書きしない。
- 保存失敗時に一時ファイルや部分更新を残さない。

### プロンプト・会話

- 9値と強い表現状態が固定JSON境界へ入る。
- OFFとONでアプリ独自の表現指示が切り替わる。
- ペルソナ値が上位指示として解釈されない。
- 保存前に開始済みの応答は変わらず、次のメッセージで新値を使う。

### Tauri境界

- 設定ウィンドウだけが取得・保存コマンドを利用できる。
- 不正なキャラクターID、範囲、同意状態をRust側で拒否する。

### React UI

- キャラクターごとに9値を読み込み、切替できる。
- 数値、端点、ラベル、キーボード操作が利用できる。
- 赤い警告、確認文、免責文を表示する。
- 確認チェックなしではON確定できない。
- OFF、既定値復帰、保存成功、保存失敗、未保存切替を扱う。

## 10. 復旧とロールバック

作業は `feat/personality-dark-triad` ブランチに限定する。実装前の状態へ戻すにはブランチを破棄して `main` へ戻る。データ面では、v1読込時に自動書込みを行わず、検証済みの明示保存時だけv2へ置換する。

v2から機能をロールバックする場合、旧アプリはv2を未知スキーマとして拒否する可能性がある。そのため公開前に、v2設定から既存v1フィールドだけを抽出する復旧手順または互換読込方針を実装計画で明示する。ユーザーデータを削除してのロールバックは行わない。

## 11. 完了条件

- キャラクターごとに9指標と強いダーク表現設定を編集・保存できる。
- 警告、確認、免責が承認文面どおり表示される。
- 強いダーク表現は既定OFFで、有効な明示同意なしには保存できない。
- 保存値が次のユーザーメッセージから反映される。
- v1プロフィールの既存内容が失われない。
- capability、契約、移行、プロンプト、UIの関連テストが通る。
- TypeScript型検査、Rust静的解析、対象ビルドの実行結果と未検証事項を報告する。
