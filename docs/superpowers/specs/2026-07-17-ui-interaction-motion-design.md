# UIインタラクションモーション設計

**日付:** 2026-07-17
**状態:** 承認範囲を本実装済み（共通化に関する未決定事項は継続検討）
**対象:** Parallel World デスクトップUI

## 1. 目的

既存UIのクリックとホバーに、操作への反応が伝わるアニメーションを追加する。

## 2. 確定事項

- クリック操作にアニメーションを追加する。
- ホバー操作にアニメーションを追加する。
- 現在のUIレイアウトは変更しない。
- 静止時のレイアウトを維持する限り、ホバー中や押下中の一時的な拡縮、移動、傾き、透明度変化は許容する。
- メイン画面のひし形UIをホバーしたとき、ガラスが反射してきらりと光るエフェクトを表示する。

### 2.1 操作用のひし形UI

- トリガーはポインターのホバーとする。
- 対象は、メイン画面下部の画面選択用ひし形と、設定画面上部のカテゴリ選択用ひし形とする。
- 操作できない装飾用のひし形は対象外とする。
- 視覚表現は、ガラス表面で光が反射するようなきらめきとする。
- 反射光は、ひし形の右下から左上へ斜めに走らせる。
- 反射光は細い線ではなく、少し幅のある帯として表現する。
- 反射光の輪郭は、ガラス反射らしい柔らかなぼかしとする。
- 反射光の配色は、青から紫へ変化するグラデーションとする。
- 反射光は暗い青紫を避け、明るいスカイブルー、白に近いガラスハイライト、淡いラベンダーをつないだ清潔感のある配色とする。
- 反射光は、ホバーしたことを利用者が明確に認識できる強さとする。
- ライトテーマを調整基準とし、白い背景と選択済みの明るい面色のどちらでも反射を認識できる彩度と不透明度を確保する。
- 1回のホバー中に、反射エフェクトを1回だけ再生する。
- ポインターが離れてホバー状態が解除された後は、再びホバーするたびに再生する。
- 1回の再生時間は60fps換算で約10フレーム、約167msとする。
- 現在選択中のシアン塗りのひし形にも、同じ反射エフェクトを表示する。
- 設定画面左上の「設定」ひし形は現在位置を示す静的表示であり、操作メニューではないため、ホバー、押下、クリック成立の各アニメーションを適用しない。
- 現行実装上の対象は、`.screen-tabs button` と `.category-crown button` に該当する。
- クリック時は、現行の押下中に約3%縮む反応を維持する。
- クリックが成立して選択を確定した後は、対象をわずかに拡大しながら、周囲へ柔らかな光がぽわっとにじむ演出を表示する。
- 周囲光は単色ではなく、アクセントを感じるグラデーション発光とする。
- 発光グラデーションの配色は、シアンから青紫へ変化させる。
- ひし形に近い内側をシアンとし、外側へ広がるほど淡い青紫になる放射状のグラデーションとする。
- 発光は、ひし形の外周から辺長の半分より少し小さい範囲まで広げる。
- クリック成立時の発光はホバー反射より明確に強くし、選択確定を認識できる強さとする。
- 発光はクリック直後に素早く強まり、一瞬だけピークを作った後、消滅完了までに減衰させる。

### 2.2 次のメニューの表示

- 本節の表示演出は、メイン画面から設定画面へ入る場合だけに適用する。
- 設定用ひし形をクリックした直後から、クリック成立演出と並行して設定画面への遷移を開始する。
- 設定画面への遷移開始と同時に、透明な状態から画面上部へ背景グラデーションを徐々に表示する。
- 背景グラデーションはテーマごとに視認性のよい配色を用意し、画面の高さ50%地点までに徐々に完全な透明へ変化させる。下半分には色を残さない。
- ダークテーマでは上端を黒とする。
- ライトテーマでは上端を白とする。
- 次のメニューに含まれるひし形項目を、左から1つずつ順番に表示する。
- 各ひし形は透明な状態から通常の表示状態へ変化させる。
- 個々の表示は過剰な演出にせず、左から右へ流れるような連続感を重視する。
- 各ひし形の位置と大きさは変化させず、透明度だけで表示する。
- 上部グラデーションと、ひし形メニューの順次フェードインは同時に開始する。
- ひし形は段ごとではなく、画面上のX座標が左にあるものから順に表示する。
- 現行配置での表示順は、`音声` → `診断` → `AI` → `表示` → `キャラクター` → `更新` → `データ` とする。
- 7個のカテゴリ用ひし形は、左右端を基準に共通の間隔値を使用し、横方向の中心間隔を均等にする。
- 同じ段に並ぶカテゴリ用ひし形同士は角を接触させず、上下段の間に余白がある状態と釣り合う、明確で均等な横方向の余白を設ける。
- 各ひし形のフェードイン開始間隔は約33ms（1/30秒）とする。7個目は開始から約200ms後にフェードインを開始し、全体は750msで完全表示する。
- 全体をゲームUIらしい連続した遷移として見せる。
- 次のメニューの表示演出は、60fps換算で約45フレーム、750msで完了する。描画フレームレートを45fpsへ制限するものではない。
- 性格画面と会話画面の表示演出は、設定画面の表示演出を流用せず、それぞれ固有のトランジションとして別々に設計する。
- 拡大、周囲の発光、消滅と、設定画面および次のメニューの表示を同時並行で進行させる。
- ぼかし、拡大、消滅の対象はクリックしたひし形だけとし、ほかのひし形には同じ消滅演出を適用しない。
- 次のメニューへは、ゲームUIのように途切れを感じさせずシームレスに遷移する。
- 「周囲の発光＋拡大＋消滅」のクリック成立演出は、メイン画面下部のひし形だけに適用する。
- 設定画面のカテゴリ用ひし形では、クリック成立後の消滅演出を使用しない。ホバー反射と現行の押下縮小は維持する。
- クリック成立から消滅完了までの時間は、60fps換算で約30フレーム、約500msとする。
- 消滅時の拡大は、元の大きさからわずかに大きくなる程度とする。具体的な倍率は実装時の視覚調整値とする。
- メイン画面では「設定」と「会話」のひし形位置を入れ替え、「会話」を左上、「設定」を下中央に配置する。設定画面左上の静的な「設定」表示位置は変更しない。
- メイン画面の3つのひし形は、上段2つと下中央1つの組み合わせでハート形を内包するシルエットとして扱う。項目名を入れ替えても、ひし形の大きさ、中心位置、接続関係を変更せず、ハート形を壊さない。
- ハート形の配置枠は、ひし形1個の大きさを基準に幅2個分、高さ1.5個分とし、画面サイズや拡大率が変化してもこの比率を維持する。枠とひし形を別々の拡大式で計算しない。

### 2.3 性格画面のトランジション

- 性格画面へのトランジションは、クリックした「性格」のひし形を起点とし、そこから画面全体へ演出を広げる。
- クリックした操作と次画面の表示が連続して見えるよう、起点を途中で切り替えない。
- 起点から、細い半透明のひし形輪郭を3層に分けて外側へ展開する。
- 3層の配色は、明るいシアン、白に近いハイライト、淡い紫の順とする。
- 各輪郭は約70msずつ開始をずらし、1層あたり約760msで画面外まで広げながら透明にする。
- 性格画面本体は、同じ起点からひし形状の表示領域が広がるように現し、約800msで完全表示する。輪郭を含む演出全体は約920msで完了する。
- モック内の「価値観」「話し方」「距離感」などの画面内容はトランジション確認用であり、本決定の対象には含めない。

### 2.4 会話画面のトランジション

- 会話画面へのトランジションは、クリックした「会話」のひし形を起点とし、そこから画面全体へ演出を広げる。
- 性格画面と同じ連続性を持たせる一方、輪郭はひし形ではなく細い半透明の円形とする。
- 円形輪郭は3層とし、配色は明るいシアン、白に近いハイライト、淡い紫の順とする。
- 各輪郭は約70msずつ開始をずらし、1層あたり約760msで画面外まで広げながら透明にする。
- 会話画面本体は、同じ起点から円形の表示領域が広がるように現し、約800msで完全表示する。輪郭を含む演出全体は約920msで完了する。
- モック内の会話履歴や話題などの画面内容はトランジション確認用であり、本決定の対象には含めない。

### 2.5 モック承認基準

- 2026-07-17に提示されたモック画像2枚について、設定カテゴリの同一段にあるひし形同士が接触している点を除き、表示されたレイアウト、配色、反射表現、画面遷移はイメージどおりとして承認済みとする。
- 今後の調整では、明示的な変更要望がない限り、この承認済み部分を変更しない。
- 2026-07-18時点のモックで確認したアニメーションと、ハート形の`ひし形1 : 横幅2 : 高さ1.5`の比率を実装基準として承認する。

### 2.6 既知のモック修正要件

- ホバーの判定領域は、画面上に見えているひし形の輪郭と一致させる。透明な正方形の角や、隣接するひし形と重なる領域で別項目のホバーアニメーションを開始しない。
- 設定画面への遷移中は、元のメイン画面を背景として維持し、その上に半透明の上部グラデーションと設定内容を重ねる。
- 設定画面の全面を不透明な背景で即座に覆ったり、元画面を薄い複製背景へ入れ替えたりしない。

## 3. 未決定事項

- ゲームUIらしいシームレスさを、ひし形以外の操作にも共通方針として適用するか
- 対象コンポーネントと対象外コンポーネント
- ホバー、押下、クリック成立後の各フィードバック
- 継続時間、イージング、移動量、拡縮率
- 画面遷移やパネル開閉を対象に含めるか
- マウス、キーボード、タッチ相当操作の扱い
- `prefers-reduced-motion` への対応
- 非活性、処理中、連打時の挙動
- 実装方式と検証基準

## 4. 作業用語（暫定）

- **ホバーフィードバック:** ポインターが操作対象の上にある間だけ表示する反応。
- **押下フィードバック:** ボタンを押してから離すまでの反応。
- **クリック成立フィードバック:** クリック操作が成立した直後の短い反応。
- **状態遷移モーション:** パネルの開閉や画面切替など、UI状態の変化をつなぐ動き。

作業用語はヒアリングを進めるための暫定定義であり、確定事項ではない。
