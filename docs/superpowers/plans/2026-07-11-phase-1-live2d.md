# Phase 1 Live2D Display Implementation Plan

**Goal:** Character WindowへLive2Dモデルを透過表示し、待機モーション、表情変更、ドラッグ移動、クリック透過、DPI対応、位置・サイズ復元を実装する。

**完了条件（docs/product/基本設計.md Phase 1）:**
- キャラクターをデスクトップへ安定表示できる
- 設定変更で表情とモーションを切り替えられる
- 再起動後に位置とサイズが復元される

## アーキテクチャ決定

1. **SDKのvendor方針**
   - Cubism Web Framework 5-r.5（TSソース59ファイル + WebGLシェーダー、Live2D Open Software License）を `packages/live2d-runtime/vendor/framework/` へコミットする。LICENSE.md を同梱する。
   - Cubism Core は `RedistributableFiles.txt` により `live2dcubismcore.js / .min.js / .d.ts` の再配布が許可されているため、`.min.js` を `apps/desktop/public/live2d/core/` へ、`.d.ts` を `packages/live2d-runtime/vendor/core/` へコミットする（CSP `script-src 'self'` 内で配信）。
   - モデル（Live2Dサンプルデータ規約）はコミットしない。開発用sync scriptで app data の `characters/` へコピーする。既定devモデルは `epsilon_free`（表情8種、Idleモーション、物理演算）。

2. **React非依存controller（設計spec 2章）**
   - `Live2DController` は `CubismRuntime` インターフェースにのみ依存する。状態機械・API（`attach/loadModel/setExpression/startMotion/dispose/resize`）はfake runtimeで単体テストする。
   - `CubismFrameworkRuntime`（実装アダプタ）がFramework/Core/WebGLを扱う。WebGL実描画は単体テスト対象外とし、devでの実機確認とする。

3. **モデル配信経路**
   - モデルは app data `characters/` に置き、Rustが `get_character_manifest` で解析、フロントは `convertFileSrc` の asset URL で読み込む。
   - `assetProtocol` scope は `$APPDATA/characters/**` のみ。CSPへ `asset: http://asset.localhost` を connect-src / img-src に追加する（無効化はしない）。

4. **表情・モーション切替のIPC**
   - Settings → `set_expression` / `start_motion` command（Rustがmanifestに対して名前を検証）→ character window へ event（`character-expression` / `character-motion`）→ controller適用。

5. **位置・サイズ復元**: 公式 `tauri-plugin-window-state` 2.x を採用する。

6. **クリック透過**: Rustが `cursor_position()` を~30Hzでポーリングし window相対座標を character window へ event送信。フロントはWebGL alpha読みでhit判定し、変化時のみ `set_click_through` を invoke。`set_ignore_cursor_events` 中もIPC eventは届くため復帰可能。

## Tasks

### Task 1: live2d-runtime パッケージとcontroller状態機械
- vendor: framework src/shaders、core d.ts、core min.js（public）、ライセンス配置、`.gitignore` へ `apps/desktop/public/live2d/models/` 追加
- `packages/live2d-runtime`: package.json（typecheck/test）、tsconfig（vendor含む）、vitest
- TDD: `Live2DController`（idle→attaching→ready→model-loaded / core-unavailable / disposed、resize、fake runtime注入）

### Task 2: CubismFrameworkRuntime アダプタ
- `CharacterModel`（promise版 LAppModel 相当: setting/moc/textures/expressions/physics/pose/blink/breath/look/UpdateScheduler）
- 描画loop（rAF、DPR対応projection）、idle自動再生、`setExpression`/`startMotion`、alpha hit-test
- TDD: URL解決・motion名マッピング等の純粋ロジック

### Task 3: Rust manifest / commands / capability / window-state
- `character/manifest.rs`: model3.json解析（合成fixtureでTDD）
- commands: `get_character_manifest` / `set_expression` / `start_motion` / `set_click_through`（検証+event emit）
- capability更新+拒否テスト、CSP/assetProtocol、`tauri-plugin-window-state`
- DTO: `CharacterManifestDto` / `MotionGroupDto`（ts-rs再生成）

### Task 4: フロントエンド統合とsync script
- character.html へ core script、`CharacterWindow` controller接続、状態→StatusBadge、`data-tauri-drag-region`
- `SettingsWindow` キャラクターパネル（表情select、モーション再生）
- `tools/scripts/sync-live2d-dev-assets.mjs`
- component tests（tauri api mock）

### Task 5: クリック透過と受け入れ
- Rust cursor poll → event → フロントhit判定 → `set_click_through`
- 全品質ゲート + `tauri build --debug --no-bundle` + docs/development/worklogs/2026-07.md更新
